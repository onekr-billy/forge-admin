## 关键技术参考

### H5 低代码渲染引擎组件链
```
PageSectionRenderer.vue (570行)
  ├── sections: 分区配置（card/child_table）
  ├── mainFields + mainData: 主表字段和数据
  ├── children + childData: 子表配置和数据
  ├── mode: 'edit' | 'detail'
  ├── dictOptions: 字典选项
  ├── flowInteraction: 流程交互配置
  └── 内部使用 LowcodeForm.vue → LowcodeField.vue 渲染每个字段
```

### FlowDesignPage Props
```javascript
{
  embedded: Boolean,           // 是否嵌入模式
  modelId: String | Number,    // 流程模型 ID
  businessObjectCode: String,  // 业务对象编码
  businessObjectName: String,  // 业务对象名称
  businessFormKey: String,     // 业务表单 key
  applicationId: String | Number, // 应用 ID
  businessEntryRoute: String,  // 业务入口路由
  codeApp: Boolean,            // 是否代码应用
}
// emits: ['close', 'saved', 'deployed']
```

### BusinessFlowBindingPanel 弹窗模式参考
```html
<n-modal v-model:show="flowDesignerVisible" class="flow-designer-modal" :mask-closable="false">
  <section class="flow-designer-modal-shell">
    <FlowDesignPage
      v-if="flowDesignerVisible"
      embedded
      :model-id="selectedFlowModelId"
      :business-object-code="objectCode"
      :business-object-name="objectName || objectCode"
      :application-id="applicationId"
      :code-app="codeApp"
      @close="handleFlowDesignerClose"
      @saved="handleFlowDesignerSaved"
      @deployed="handleFlowDesignerSaved"

  </section>
</n-modal>
```

### A2. 各环节详细分析

#### 1. 低代码页面/表单引擎（完成度 85%）

**已有能力：**
- 对象设计器 `object-designer.[objectCode].vue` 完整支持字段管理、关系配置、表单/列表/详情设计
- `BusinessFormDesigner.vue` 2684 行，支持拖拽式表单设计
- `ForgeFormDesigner.vue` 原生三栏布局表单设计器
- `PortalPageRenderer.vue` 支持 GridBlock、AiCrudPage、外部 URL 等多种渲染
- `BusinessListDesigner.vue` 列表设计、`BusinessDetailDesigner.vue` 详情设计

**关键缺口：**
- **H5 端无低代码应用门户**：H5 目前只有 `todo.vue` 和 `todo-detail.vue`，用户无法在移动端浏览低代码应用页面、提交表单或查看列表
- **运行态表单校验不足**：H5 端 `normalizeFields` 只做基础类型识别，缺少正则校验、跨字段联动校验
- **无表单联动引擎**：字段之间的显隐/联动/计算规则没有可视化配置和运行时引擎

#### 2. 审批流程引擎（完成度 80%）

**已有能力：**
- `FlowTaskService` 完整支持 approve/reject/claim/delegate/return/terminate
- 两种流程设计器：BpmnModeler（BPMN.js 标准）和 DingFlowDesigner（钉钉样式自研）
- PC 端四视图：待办、已办、发起、抄送
- `BusinessFlowBindingPanel` 支持流程模型选择、变量映射、业务记录绑定、回调动作配置

**关键缺口：**
- **SLA 超时处理缺失**：没有任务超时配置、超时自动提醒、超时自动转办/升级机制
- **加签/会签不支持**：当前只支持单人签收→审批
- **流程版本回滚缺失**：流程发布后无法回退到历史版本

#### 3. 消息通知（完成度 70%）

**已有能力：**
- 4 通道：站内信（`forge-plugin-message`）、邮件（SMTP）、短信（阿里云）、企微卡片（`WeComCallbackConnector`）
- 模板引擎 + 发送记录 + 已读回执
- `FlowTaskNotifyListener` 在流程节点流转时自动发送通知

**关键缺口：**
- **无通知规则配置 UI**：管理员无法在页面上配置「哪些节点通知谁、用什么通道」
- **无失败重试机制**：消息发送失败后直接丢弃，无重试队列
- **无通知模板可视化编辑**：模板变量只能手写，没有字段选择器

#### 4. 单据审批/待办（完成度 90%）

**已有能力：**
- PC 端四视图 + H5 端完整审批（表单渲染/签名/转办/退回/终结）
- 审批记录时间轴 + 流程进度图
- 表单暂存 + 必填校验

**关键缺口：**
- **缺少打印/导出审批单**：企业合规存档刚需
- **PC 端待办表单渲染也是扁平化**：PC 端 `todo.vue` 虽比 H5 好，但业务表单渲染本质上也是扁平化处理

#### 5. 企业集成（完成度 60%）

**已有能力：**
- 企微全链路：OAuth 登录、通讯录同步、消息推送、回调处理
- `CollaborationProvider` 抽象层 + `TodoConnector`/`DirectoryConnector`/`CallbackConnector` 接口
- Webhook 事件推送 + Redis Pub/Sub

**关键缺口：**
- **企微待办用的是「消息卡片」而非「原生待办」**：当前推送 textcard 消息到企微，用户点击跳转到系统页面处理。但企微侧没有原生待办的状态同步（审批后企微卡片不会自动消失/标记已办）
- **无双向待办同步**：系统内审批状态变更后，企微侧不会自动更新
- **无钉钉/飞书实现**：CollaborationProvider 只有企微实现

#### 6. 业务流程编排（完成度 65%）

**已有能力：**
- `BusinessFlowBindingPanel` 1469 行：流程模型选择、变量映射、回调动作
- `BusinessCodeFormProvider` 代码级表单提供
- 流程发起/回调/状态流转

**关键缺口：**
- **面板已标记 legacy 只读**：`legacyReadOnly = true`，用户在对象设计器里能看不能改
- **无触发器设计器**：没有可视化配置「当 XX 条件满足时自动发起流程」
- **无自动化规则引擎**：缺少条件→动作的规则配置

#### 7. 数据推送（完成度 30%）

**已有能力：**
- 流程级 Webhook（节点流转时推送）
- Redis Pub/Sub 事件总线

**关键缺口：**
- **无 CRUD 级数据推送**：低代码对象的增删改不会自动推送到外部系统
- **无外部系统数据同步**：没有 ETL 或数据映射机制

### B2. 痛点一：H5 待办表单渲染（已解决 ✅）

**问题本质：** PC 端精心设计的表单布局，到 H5 审批时变成了扁平的字段堆叠列表。

**原因：** `todo-detail.vue` 使用 `normalizeFields()` 只识别基础类型（input/textarea/select/date/file），丢弃了所有布局信息（分区、列、条件显隐）。

**解决方案（已实现）：**
- 创建 `business-task-form-adapter.js` 将后端数据转换为标准格式
- 改造 `todo-detail.vue` 使用已有的 `PageSectionRenderer` 组件
- 复用 H5 已有的低代码渲染引擎（LowcodeForm → LowcodeField）

### B3. 痛点二：业务流程绑定审批流程的跳转体验（已解决 ✅）

**问题本质：** 4 个页面层级、3 次跳转，配置体验碎片化。

**当前导航链路：**
```
① 应用中心 /app-center
  → ② 应用工作台 /app-center/application/PRESALE_REGISTRATION
       → 侧边栏「业务流程」Tab → 引导卡「已移入应用设计器」
    → ③ 应用运行态(设计模式) /application-runtime/PRESALE_REGISTRATION?edit=1
         → 左侧导航：页面 / 数据 / 业务流程 → 点「业务流程列表」
         → 点某个流程「打开画布」
      → ④ 流程设计器(独立页面) BusinessProcessDesigner
           → 设计审批节点、表单权限 → 保存 → 返回 ③
```

**体验断点：**
1. ②→③ 的跳转是「假」的：用户看到「已移走」引导卡，制造认知断裂
2. ③→④ 是全屏切换：`router.push` 跳到独立页面，上下文丢失
3. 对象设计器里的 `BusinessFlowBindingPanel` 是只读的（`legacyReadOnly = true`）
4. 流程绑定和流程设计分散在两个地方

**体验断点图：**
```
应用工作台               应用设计器(运行态)          流程设计器
┌──────────┐           ┌──────────────────┐       ┌──────────────────┐
│ 引导卡    │ ──跳转──→ │ 业务流程列表      │ ──跳转──→│ BPMN/钉钉画布     │
│ "已移走"  │           │ + 对象设计器(只读) │       │ 节点配置/表单权限 │
│           │           │                  │ ←──返回──│                  │
└──────────┘           └──────────────────┘       └──────────────────┘
     ↑ 认知断裂              ↑ 上下文丢失            ↑ 独立页面无关联
```

**解决方向：** 把流程绑定 + 流程设计收敛到一个内嵌面板，去掉跳转。

**策略 A（渐进式，已实现 ✅）：**
- 在应用设计器的「业务流程」面板里内嵌流程画布
- 参考 `BusinessFlowBindingPanel` 已有的 `flowDesignerVisible` modal 弹窗模式
- 把独立页面改为内部全屏面板，而不是 `router.push` 跳新页
- 详见本文「任务 4」的实现详情

**策略 B（彻底重构，工作量大，暂不推荐）：**
- 把 `BusinessProcessCanvas` 作为统一入口
- 流程绑定配置和节点设计都在画布上完成
- 不用在「列表」和「画布」之间切换
