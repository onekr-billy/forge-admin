# H5 运行时多区域单页改造方案

## 改造目标

当前 `lowcode-runtime.vue` 表单模式是"主表单 + 子表"的平铺布局，PRD 原型图要求的是**多卡片单页 + 底部操作栏 + pill 选择器 + 底部抽屉**的移动端交互。本次改造通过在 `formDesignerSchema` 中新增可选的 `pageSections` 配置，让运行时按 section 渲染，向后兼容现有配置。

## 方案架构

```
formDesignerSchema
  ├── components[]          ← 现有：字段组件定义（保留不动）
  ├── layout                ← 现有：表单布局（保留不动）
  ├── settings.governance   ← 现有：fieldEvents/permission/offlineDraft（保留不动）
  └── pageSections[]        ← 新增：多区域分区配置（可选）
        ├── sectionId
        ├── sectionType: card | child_table
        ├── title
        ├── fields[]           ← card 类型：引用 components 中的字段
        ├── relationKey        ← child_table 类型：引用 masterDetailConfig.children
        ├── displayMode: inline_grid | bottom_sheet | card_list
        └── visibleInModes: [create, edit, detail]
  └── bottomBar             ← 新增：底部固定操作栏（可选）
        └── actions[]
              ├── type: save | reset | action | cancel
              ├── actionCode  ← type=action 时引用业务动作
              ├── label
              ├── variant: primary | secondary | danger
              └── displayCondition
```

## 改动清单

### 第 1 步：新建移动端组件（forge-h5-ui/src/components/lowcode/）

**1.1 `CardSection.vue`** — 卡片分区容器

Props: `title`, `collapsible`, `defaultExpanded`, `visible`
内容通过 slot 渲染。顶部标题栏 + 可折叠内容区。样式复用现有 `.runtime-form-card` 的圆角白底阴影风格。

**1.2 `PillSelect.vue`** — 药丸选择器

Props: `options` (来自字典), `modelValue`, `dictType`
渲染为水平排列的 pill 按钮组，选中态高亮。替代 dictSelect 在移动端的下拉体验。支持 `clearable=false` 时强制选中一个。

**1.3 `BottomSheet.vue`** — 底部抽屉

Props: `visible`, `title`, `maxHeight`
从底部滑入的半屏面板，带遮罩层。点击遮罩或向下滑动关闭。用于操作日志等只读子表的展示。

### 第 2 步：扩展 H5 运行时渲染逻辑（lowcode-runtime.vue）

**2.1 新增 section 模式判断**

在 `<template v-else>`（非 list 模式）中，增加判断：

```
const hasPageSections = computed(() =>
  Array.isArray(formDesignerSchema.value?.pageSections) &&
  formDesignerSchema.value.pageSections.length > 0
)
```

- `hasPageSections === true` → 渲染 `<PageSectionRenderer>`（新增）
- `hasPageSections === false` → 渲染现有逻辑（向后兼容）

**2.2 新增 section 渲染分支**

在 template 中 `<template v-else>` 内部增加：

```vue
<template v-if="hasPageSections">
  <PageSectionRenderer
    :sections="pageSections"
    :main-data="mainData"
    :children="visibleChildren"
    :child-data="childData"
    :mode="mode"
    :dict-options="dictOptions"
    :runtime-context="runtimeContext"
    :bottom-bar="formDesignerSchema.bottomBar"
    @main-field-event="handleMainFieldEvent"
    @child-field-event="handleChildFieldEvent"
    @add-child-row="addChildRow"
    @remove-child-row="removeChildRow"
    @bottom-action="handleBottomAction"
  />
</template>
<template v-else>
  <!-- 现有的 runtime-form-card + runtime-child-card 逻辑 -->
</template>
```

**2.3 新建 `PageSectionRenderer.vue`**（forge-h5-ui/src/components/lowcode/）

核心渲染组件，职责：
- 遍历 `pageSections` 数组
- `sectionType === 'card'` → 用 `CardSection` 包裹，内部用 `LowcodeForm` 渲染指定 fields（从 components 中按 fieldCode 过滤）
- `sectionType === 'child_table'` → 根据 `displayMode`：
  - `inline_grid` → 内联可编辑子表（现有 child row 渲染逻辑，但不带卡片头）
  - `bottom_sheet` → 只读列表 + 触发按钮，点击打开 `BottomSheet`
  - `card_list` → 每行一个卡片的列表展示
- 底部渲染 `bottomBar`（固定定位，sticky bottom）

**2.4 底部操作栏处理**

新增 `handleBottomAction(action)` 方法：
- `type === 'save'` → 调用现有 `save()` 方法
- `type === 'reset'` → 清空 mainData + childData，重新 `initializeForm()`
- `type === 'action'` → 调用 `runAction(action)`，传入 mainData 作为 row
- `type === 'cancel'` → `goList()`
- 支持 `displayCondition`（如 `status == DRAFT`）控制按钮显隐

### 第 3 步：扩展字段组件类型支持（LowcodeField.vue）

**3.1 新增 `pillSelect` 字段类型**

在 `LowcodeField.vue` 的组件类型映射中增加：
- `pillSelect` → 使用 `PillSelect` 组件
- 自动从 `dictOptions[field.dictType]` 获取选项
- 发射 `change` 事件，兼容现有 `field-event` 机制

**3.2 子表字段在 section 模式下的渲染优化**

当 section 的 `displayMode === 'inline_grid'` 时，子表行的 `LowcodeForm` 使用紧凑栅格布局（单行展示条码+名称+数量），而非默认的 2 列表单布局。

### 第 4 步：更新预售种子 SQL

**新建 `V1.0.1XX__update_presale_page_sections.sql`**

在 `@ps_form_schema` 变量中增加 `pageSections` 和 `bottomBar` 配置：

```sql
-- 在 @ps_form_schema 的 JSON_OBJECT 中增加：
'pageSections', JSON_ARRAY(
  JSON_OBJECT('sectionId', 'guide_info', 'sectionType', 'card',
    'title', '导购信息', 'collapsible', false,
    'fields', JSON_ARRAY('salesUserName', 'staffNo', 'storeName')),
  JSON_OBJECT('sectionId', 'member_info', 'sectionType', 'card',
    'title', '会员信息', 'collapsible', false,
    'fields', JSON_ARRAY('memberPhone', 'memberId', 'memberName')),
  JSON_OBJECT('sectionId', 'payment', 'sectionType', 'card',
    'title', '收款信息', 'collapsible', false,
    'fields', JSON_ARRAY('payMethod', 'staticPaymentNo', 'staticPaymentInfo', 'cashAmount'),
    'fieldOverrides', JSON_OBJECT(
      'payMethod', JSON_OBJECT('componentKey', 'pillSelect')
    )),
  JSON_OBJECT('sectionId', 'presale_items', 'sectionType', 'child_table',
    'relationKey', 'presale_items', 'title', '商品明细',
    'displayMode', 'inline_grid'),
  JSON_OBJECT('sectionId', 'operation_logs', 'sectionType', 'child_table',
    'relationKey', 'operation_logs', 'title', '操作日志',
    'displayMode', 'bottom_sheet',
    'visibleInModes', JSON_ARRAY('edit', 'detail'))
),
'bottomBar', JSON_OBJECT(
  'actions', JSON_ARRAY(
    JSON_OBJECT('type', 'reset', 'label', '清空', 'variant', 'secondary'),
    JSON_OBJECT('type', 'action', 'actionCode', 'submit_presale',
      'label', '提交', 'variant', 'primary',
      'displayCondition', 'status == DRAFT')
  )
)
```

然后 UPDATE `ai_business_object.designer_options` 和 `ai_crud_config.options` 中的 `formDesignerSchema`。

### 第 5 步：样式适配

**5.1 卡片分区间距**

各 CardSection 之间 `margin-bottom: 24rpx`，内部 padding `26rpx`，复用现有 `.runtime-form-card` 样式。

**5.2 底部操作栏**

固定在视口底部，`position: fixed; bottom: 0`，带安全区域 padding。两个按钮等宽分布。

**5.3 pill 选择器**

水平排列，自动换行，pill 间距 `12rpx`。选中态：蓝色背景白字；未选中：白底灰字灰边框。

## 向后兼容保证

- `pageSections` 是可选字段，不存在时走现有渲染逻辑
- `bottomBar` 是可选字段，不存在时走现有 `runtime-footer-actions`
- `fieldOverrides` 只在 section 模式下生效，不影响现有 components 定义
- 现有 fieldEvents、businessActions、masterDetailConfig 机制完全复用
- 子表的 `LowcodeForm` 实例引用和 `childFormRefs` 管理逻辑不变
