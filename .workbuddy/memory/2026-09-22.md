## 掘金：系列第 11 篇（Redisson 锁续期）
- 交付：`output/掘金-Redisson锁配了600秒实际只防5秒watchdog为什么没启动.md`
- 兑现上篇（cache）结尾预告的"Redisson 锁续期 leaseTime/watchdog"
- **核心机制讲透**：`tryLock(wait, lease, unit)` 三参只要传了 leaseTime → watchdog 不启动；`tryLock(wait, unit)` 两参才走 watchdog（默认 30s TTL / 每 10s 续期 / JVM 挂了最多再活 30s）
- **最有价值的发现：同一项目一正一反对照实现**
  - ❌ `RedissonLockManager`（idempotent）：三参 tryLock + 直接注入 RedissonClient（无降级）+ boolean 返回 + 成功路径默认不解锁
  - ✅ `JobExecutionLockManager`（job）：两参 `tryLock(0L, unit)` 走 watchdog + `ObjectProvider.getIfAvailable()` 优雅降级 + `LockHandle implements AutoCloseable`（try-with-resources）+ 三态返回（ACQUIRED/CONTENDED/UNAVAILABLE）
  - 这个对照比讲官方文档有说服力得多，已做成四维度对比表
- 5 个坑：①`annotation.expire()` 死变量（声明即弃，锁租期永远来自 LockProperties.leaseTime=5000）②三参 tryLock 无 watchdog → 业务超时并发（"扣3次款"根因）③`deleteKeyAfterSuccess` 默认 false → 成功不解锁、失败才解锁，幂等窗口实际=5s 租期 ④`ReturnCache` 的 `Thread.sleep(100)` 硬睡一次即放弃（无依据/无重试/惊群）⑤`LockProperties.enabled` 死配置（全项目无读取点）
- 做对的地方：`isHeldByCurrentThread()` 前置检查（防止释放别人的锁）/ InterruptedException 恢复中断标志 / 异常路径立刻解锁 / LockManager 接口 + `@ConditionalOnMissingBean`
- 如实声明：`@Idempotent` 全项目零业务接入（只有测试），坑为源码推演非线上事故
- 新增缺陷索引 18/19/20 到 MEMORY.md（累计 20 个）
