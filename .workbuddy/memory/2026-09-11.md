### 本轮新核实的源码事实（很有价值，后续可复用）
- **注册链路**：MybatisPlusConfig 用 `@Autowired(required=false) List<InnerInterceptor>` 收集自定义拦截器 → 先注册它们 → 再分页 → 再乐观锁。顺序由 Bean 注册顺序（受 `@AutoConfigureOrder` 影响）决定
  - DataScopeAutoConfiguration: `@AutoConfigureOrder(HIGHEST_PRECEDENCE)` → datascope 先
  - TenantAutoConfiguration: `HIGHEST_PRECEDENCE + 10` → tenant 后
  - **两个拦截器都没有 getOrder()/@Order，也没有断言顺序的测试** → 隐式契约（文章第 1 坑）
- **CountOnePaginationInnerInterceptor**（forge-starter-orm，自定义）：把 `COUNT(*)` 改成 `COUNT(1)`，原因写在类注释里——深嵌套查询时 JSqlParser 解析 `SELECT COUNT(` 会失败，"COUNT(1) 可被当前租户和数据权限拦截器稳定解析"。→ 本文最硬核发现
- **`_mpCount` / `_COUNT`**：分页 count 查询的 MappedStatement 后缀，DataScopeInterceptor 靠 `replaceAll("(_mpCount|_COUNT)$","")` 反查原方法配置，否则 count 上数据权限失效（总数对不上）
- **上下文容器不一致**：TenantContextHolder 用 TransmittableThreadLocal + 保存/恢复（可嵌套）；DataScopeContextHolder 用**普通 ThreadLocal** + `clearSkip()` 直接清（嵌套会覆盖外层，线程池不传递）
- MyBatis-Plus 版本 3.5.7（forge-dependencies/pom.xml）
