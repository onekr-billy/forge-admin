## websocket 模块核实结果（599 行 / 8 类 / 6 个测试）
全量核实：`WebSocketConfig` / `AuthenticatedWebSocketChannelInterceptor` / `WebSocketAuthenticationProvider` / `WebSocketProperties` / `MessagePushServiceImpl` / `IMessagePushService` / `WebSocketMessage` / `MessageType`(14 种) / 6 个契约测试

### 6 个坑（全部源码核实）
1. **`enableSimpleBroker("/queue","/topic")` 是内存代理** → 多实例部署推送静默丢失，无 broker-relay 扩展点。`convertAndSendToUser` 调用成功 ≠ 有人收到
2. **`@Async` 依赖别的 starter**：websocket 模块自己**没有 `@EnableAsync`**；全项目仅 api-config:25 / excel:19 / flow:44 三处有。不引这三个之一，`pushToUserAsync` 就是同步（隐式依赖，无编译错误无警告）
3. **Principal 名字是隐式契约**：`convertAndSendToUser(userId)` → `/queue/messages-user{userId}`；客户端订阅 `/user/queue/messages` → 按 `principal.getName()` 重写。**两者必须字符串全等**，不一致时消息静默丢弃（不报错不打日志）。默认 Sa-Token 实现返回 `String.valueOf(loginId)`，业务侧 `pushToUser(String.valueOf(loginId))` 对上了；但自定义 provider 返回用户名就断
4. **`WebSocketConfig` 无 `@ConditionalOnProperty`** → 引入 jar 即强制开启 `/ws` + SockJS，无总开关
5. **握手阶段不鉴权**：认证在 STOMP CONNECT 帧，`/ws/info` 任何人可访问 → 无连接耗尽防御。`command == null`（心跳帧）与 `DISCONNECT` 直接放行
6. **`withSockJS()` + `allowedOriginPatterns("*")` 是危险组合**（Spring 官方文档明确警告，xhr 降级传输同源限制弱 → CSWSH 风险）。默认 localhost 安全，但生产易被改成 `*`

### 做得对的地方（值得学，也是可信度来源）
- **认证缺失时 fail-closed**：`authenticationProvider == null` 直接抛 MessageDeliveryException 拒绝连接（对比 auth 模块 `@Autowired(required=false)` 的 fail-open 登录锁，是反面教材）。代价：无法做公开频道
- **禁止客户端直发 Broker**：SEND 必须是 `/app` 前缀，堵住"任意客户端向全体广播"经典漏洞
- **订阅白名单** `allowedSubscribeDestinations`（默认 `/user/**` + `/topic/broadcast`），AntPathMatcher
- **`MessageBuilder.createMessage` 重建消息**：`StompHeaderAccessor.wrap()` 后 setUser，原 message headers 不可变，必须重建再返回（很多人直接 return message 导致 Principal 丢失）
- **6 个契约测试锁安全规则**（`shouldRejectClientSendToBrokerDestination` 等）→ 安全规则写成测试比写文档可靠
- `WebSocketAuthenticationProvider` 是 `@FunctionalInterface`，auth 模块 `@ConditionalOnMissingBean` 提供 Sa-Token 默认实现
