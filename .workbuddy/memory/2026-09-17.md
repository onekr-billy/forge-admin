## 新核实的 auth 源码事实
- `forge-starter-auth` src/main 共 **4091 行**；`forge-plugin-system/strategy` 927 行（5 个类：Abstract 196 / Social 460 / UsernamePasswordCaptcha 182 / PhoneCaptcha 47 / UsernamePassword 42）
- `AuthType` **7 种**：password / password_captcha / phone_captcha / wechat / email_captcha / oauth2 / social
- 模板方法 `AbstractAuthStrategy.authenticate()` 4 步：validateRequest → doAuthenticate → checkUserStatus → handleLoginSuccess
- `AuthStrategyFactory`：精确匹配 client > 类型匹配（supportedClient==null 作兜底），ConcurrentHashMap 缓存 `authType_client → strategy`
- `AuthProperties` 默认值：**enableLoginLock=true / maxLoginAttempts=4 / lockDuration=30(min) / failRecordExpire=15(min)**
- 登录查询必须 `TenantContextHolder.executeIgnore(...)` 绕开租户过滤（登录时还不知道用户属于哪个租户）；跨租户查同名候选 → 逐个 matchPassword → 单工作区直接进 / 多工作区抛 `TENANT_SELECTION_REQUIRED` 让用户选
- 同名多租户可设不同密码，都能登录（逐候选比对的设计红利）

## 新发现的缺陷（auth，4 个，均未修复）
1. **【高危·已确认】账号锁定在密码错误时完全失效**（0916 发现，今日复核实锤）：`UsernamePasswordAuthStrategy` 第 32 行 `if (loginUser == null)` 是死代码（认证失败抛异常不返回 null）；且 `recordLoginFailure(null,...)` 因 `loginUser == null` 在第一行直接 throw，不计数不锁定
2. **死常量 key**：`LOGIN_LOCK_KEY_PREFIX = "login:lock:"` 全项目只有声明 + `clearLoginFailure` 里的 delete，**从无任何写入**；真正锁定走 `StpUtil.disable()`
3. **计数窗口 < 锁定窗口**：failRecordExpire(15min) < lockDuration(30min) → 锁定期间 failKey 已过期清零，解锁后攻击者重新获得完整 4 次机会
4. **安全开关 fail-open**：`loginLockService` 是 `@Autowired(required=false)`，Bean 缺失时 `isLoginLockEnabled()` 静默返回 false，防护消失且无任何日志
5. **提示泄露剩余次数**："还剩 N 次尝试机会" → 用户名枚举漏洞（用户不存在与密码错误返回不同信息）
