- 核心技术事实（写文章时核实过源码）：
  - 固定元工具模式：capability.search / describe / invoke / approval.get + ping，业务模块经 McpToolContributor SPI 只能贡献元工具，不能开新 transport
  - invoke 强制：幂等键必填（16-128位）、字段白名单（allowedFields）、USER_DELEGATION_REQUIRED（必须用户委托身份）
  - 人工确认走 MCP Elicitation 原生机制：客户端不支持弹窗 → 409 CONFIRMATION_REQUIRED；用户拒绝 → CONFIRMATION_DECLINED；弹窗带请求指纹防参数偷换
  - 风险分级：MEDIUM 业务动作同步执行；高风险转 PENDING_APPROVAL 人工审批流，AI 用 capability.approval.get 轮询
  - 四层漏斗：传输层认证 → 能力授权 → Elicitation 确认 → 高危审批；REST 网关与 MCP 共用 CapabilityRegistry，授权审计一套规则
  - 框架层规模：23 个 starter + 11 个业务插件（forge-plugin-mcp、capability-actions、high-risk-approval 等新插件是 0804 文章之后新增的）
