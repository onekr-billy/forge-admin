## 1. 目标与实现边界

实现 Forge 自有打印能力，与现有 Vue 3/Naive UI/Pinia、业务对象、低代码表单、应用发布和 Flowable 流程衔接。设计器、模板协议与排版代码由本项目维护。

- hiprint 仅作为功能研究参考，不引入其 npm 包，不复制 `hiprint.bundle.js`，不要求模板格式兼容。
- 复用已有二维码、条形码基础依赖时记录用途与来源；不因“自主实现”推导第三方代码许可结论。
- 首期以单条已保存业务单据打印为完整闭环；输出为同一 HTML/SVG 分页结果的预览和浏览器打印。
- 应用/流程业务状态保持原语义；打印不提交表单、不发起/完成/撤回审批、不写业务字段。
- 本次不改变现有设计预览打印行为，不整体替换低代码录入布局。

## 3. 首期用户路径

### 3.1 设计与发布

应用工作台 → 选择表单/业务对象 → 打印模板 → 新建或复制 → 拖拽字段/明细 → 合成数据预览 → 保存草稿 → 校验 → 发布模板 → 应用发布引用固定模板版本。

普通用户使用“表单、字段、明细、审批记录”语言；objectCode、providerKey、schemaVersion 放在内部协议或高级设置中。模板编码自动生成。

### 3.2 业务使用

已发布应用的列表行/详情 → 打印 → 选择可用模板（唯一时直接进入预览）→ 服务端读取授权记录 → 完成字体/资源加载与分页 → 预览 → 浏览器打印。

未保存记录、未发布模板、字段失效、权限不足或分页失败时不给出成功状态。首期不将未保存编辑内容自动写回业务记录。

### 3.3 流程使用

待办、已办、我发起的业务详情 → 打印 → 服务端解析当前任务/实例与业务记录关联 → 应用/节点模板选择规则 → 权限过滤 → 附审批记录/签名 → 预览与打印。

首期支持当前主子表低代码业务及现有采购代码表单示例。其它代码业务通过明确的打印数据提供方接入，不能对任意 formUrl 页面直接截图宣称完成集成。

### 4.1 首期分页规则

- 首期只有一个纸张配置；页眉/页脚可选择每页显示，页码由第二遍排版填充。
- 页正文按有序 section 排版。固定区块内部使用绝对坐标；流式文本和表格按实际高度排列。用户拖动区块改变顺序，拖动固定区块内部元素改变坐标。
- 表格支持固定多行表头与表头横向合并；动态数据区首期不支持跨行/跨页合并、嵌套表格。
- 文本按真实浏览器测量换行并允许按行续页；表格明细按整行换页，空表有明确空数据行为。
- 表尾合计使用平台计算/格式化后的值，不在模板里执行任意脚本；合计仅在表尾显示。
- 单行/固定区块高于单页可用区域时阻止打印，定位问题区块并提示缩小/调整；不能无限分页或直接截断。
- 建议首期保护上限：每次单据总明细 500 行、输出 50 页、资源等待 10 秒；均属于安全上限，不是性能承诺。超过时明确失败。基准验证后如需调整，先更新本 Spec。

### 4.2 显示与资源

- 数值 0、布尔 false、空字符串、null 的显示策略必须明确，不能用 truthy 判断统一丢失。
- 金额使用既有“分”数据语义，输出层定点格式化，避免浮点金额运算；长整型 ID 全程按字符串传输。
- 模板支持白名单格式化器，不提供任意 JS、SQL、HTML 脚本或任意远程 URL 取数功能。
- 图片/签名以 fileId 受控读取；允许的内联资源格式有大小限制，不把长期 token 写进模板或打印 HTML。
- 首期认证资源失败、缺字字体或超时应阻止正式输出并提示，不用空白图片代替签名。
- 页面外壳适配明暗主题；纸张输出使用明确的白底打印样式。

### 4.3 M2 阶段保存边界

- M2 提供本地草稿及可注入的异步保存适配器；默认入口明确显示“本地草稿”，浏览器只存模板协议，不存预览上下文。服务端资产保存/版本发布仍由 M3/T28 实现。
- 本地保存失败保留修改；保存期间继续编辑时仅将已提交的那份版本标为已保存，后续编辑仍保持未保存。新建、恢复、导入和离开有未保存保护。
- 编辑画布显示区块和字段占位；真实换行、图片和页数在复用 M1 的预览中计算。纸张样式保持白底，工作台跟随主题。

## 5. 模板归属、版本与流程配置

- 模板归属于应用，绑定一个业务数据源身份；页面/表单绑定与底层 objectCode 同时维护，表单重命名不靠展示名称关联。
- 一个表单可有多模板；绑定可设置默认模板，只有可用且已授权的模板进入选择列表。
- 草稿可编辑；发布生成新的不可变版本，继续编辑不覆盖旧版本。重复发布同一内容返回已有版本，乐观锁防止覆盖其他人的草稿。
- 应用发布快照存固定 templateVersionId 与绑定规则；应用回滚恢复旧引用。停用模板阻止新打印，不能通过指定旧版本绕过。
- 已发布应用引用中的模板不允许直接删除，需先解除引用/重新发布；删除用逻辑删除保留历史。
- 节点模板限制在现有流程设计器的节点面板配置，继承应用默认，限制列表取应用已发布模板的子集；不建立第二套节点配置 UI。
- 同一记录多次发起必须选择明确 processInstanceId；应用业务流程还保留 runId/processVersionId。服务端核验它们的实际关联。
- 首期打印使用当前已保存数据与当前可读审批记录，标记生成时间/流程状态；不宣称历史原样复现。

## 6. 权限与状态变更审查项

**需人工审查：本变更新增模板发布状态和权限资源，不改变审批或资金状态。**

- 模板设计：拟新增 `print:template:view/manage/publish` 权限，叠加所属应用设计权。
- 运行打印：拟新增 `print:execute`，叠加应用访问权、记录数据权限和模板绑定策略。不得授予普通用户模板管理权以解决运行访问问题。
- 流程身份：分别验证待办资格、历史参与/发起资格；只读标志不等于访问授权；前端传入 taskId/objectCode/recordId 必须与服务端关联一致。
- 字段范围取模板绑定、业务可读字段和节点/实例策略的交集；子表列和审批记录/签名也须过滤。不可见字段值不下发到预览浏览器。
- 缺少明确授权时默认拒绝；菜单种子不批量给全角色授权。流程使用者权限通过现有角色/应用发布机制显式配置。
- 操作审计记录用户、租户、记录身份、模板版本、流程实例、生成时间、结果；不记录单据正文、签名内容或鉴权 token。
- 浏览器只能报告预览/打开打印对话框等客户端事件；不能将其记为“打印机已成功出纸”。
- 模板状态、启停分别使用专用枚举/EnableStatus；状态转换在服务中统一校验，终态规则见 design.md。

## 7. 数据与迁移约束

拟新增 `sys_print_template`、`sys_print_template_version`、`sys_print_binding`、`sys_print_execution`，结构见 design.md。正式 SQL 在 /apply 时选择下一个可用 Flyway 版本，不提前修改已执行脚本。

- 表包含根规范要求的审计/租户字段，utf8mb4/InnoDB。
- 设计态主表显式逻辑删除；可重建业务键使用 BIGINT del_flag 墓碑唯一索引。
- 字典/权限种子 tenant_id=1，NOT EXISTS 防重复；列/索引变更检查 information_schema。
- 模板运行与操作日志不保存业务正文，不以执行日志代替归档快照。
- 回滚优先停用入口/模板并回退应用引用；保留新表与版本记录，不删用户模板；需要回退结构时另立迁移并备份。

## 8. 架构与实施约束

- 原生前端模块 + 独立打印后端插件 + generator 侧数据适配器，依赖单向，详细规划见 design.md。
- Pinia 管理设计器 schema、选择、历史、面板状态；预览运行状态与编辑状态分域。
- 新增 Vue 文件目标不超过 500 行，超过 800 行必须拆分；不得给超过 2000 行的存量 SFC 继续堆功能。
- 当前 `AiCrudPage.vue` 约 6785 行、`todo.vue` 约 2465 行；优先使用既有配置/小组件接入。确需修改时先完成合规拆分任务，再接入。
- 已存在 `lowcode-designer-unification` 变更，本次仅复用其字段语义/公共能力，不重建录入组件物料或改变现有表单协议。
- 前端、Java、SQL、权限与迁移执行遵循根 AGENTS.md。新增接口先定义 DTO/VO，查询 SQL 写 Mapper XML。
