# 低代码页面类型运行时适配

状态：completed（既有目录重名用例失败另记）；日期：2026-09-20。

## 范围与契约

- 修复用户 `page_page_vhu5rh` 表单页运行空白，覆盖页面运行、发布门户和设计预览共用的 GridBlockRenderer 链路。
- `form` 页面直接渲染表单及提交/重置，不自动加载列表；使用已有表单初始化、校验和 CRUD 提交，不新增写接口。
- `list` 页面直接渲染列表、查询、分页，不自动进入表单；新增/编辑仍遵循现有列表操作配置，不把“纯列表”擅自变为只读列表。
- `list-form` 保持现有列表 + 表单行为和表单设计器打开方式。
- 显式区块 formOnly 优先；否则按 objectRef.pageMode 判断，兼容仅有 pageKey=form 的旧配置；页面配置未指定时回退运行配置。显式 list/crud 不继承其他页面的 formOnly。
- 形态判断与外层高度判定共用；运行配置缺失的静态预览分支也应显示表单，不绕过静态预览提交保护。
- 不更改用户保存的 schema、不发布应用、不修改业务数据/流程，不扩展权限。无需数据库迁移。

## 实现边界

- 同域纯函数负责页面形态解析；复杂运行配置合并从巨型 GridBlockRenderer 抽出后再接入，不继续堆积页面类型逻辑。
- 共享运行配置只存对象级内容，页面形态在区块实例上计算，避免同一对象的表单/列表互相污染。
- 单测覆盖真实 GridBlockRenderer 到 AiCrudPage props 的传递，不只检查模板创建结果。
