# 低代码流程发起运行链路性能优化 Spec

> 变更名：`lowcode-flow-start-runtime-performance`
> 状态：`completed`
> 创建日期：2026-09-20

## 1. 背景与问题

第一阶段已经缩短了前端成功反馈路径，并缓存了流程发起配置。本阶段继续处理真正执行发起时的服务端耗时：

1. Admin 通过 `forge-flow-client` 调用 Flow 时仍使用 `SimpleClientHttpRequestFactory`，缺少可观测、可配置的专用连接池；连续发起时无法稳定控制连接复用、并发排队和连接保活。
2. Flow 在启动每个流程前都会查询发起人的直属领导、行政区划、当前组织角色和所属组织，即使 BPMN 完全没有引用这些变量。
3. 现有流程变量和 `TASK_CREATED` 同步待办镜像属于兼容性边界，不能为了性能改变流程路由或发起成功时序。

## 2. 目标

1. `flowRestTemplate` 使用进程级连接池复用 Admin 到 Flow 的 HTTP 连接，并允许配置连接、读写、整次调用超时以及并发连接参数。
2. 根据当前已部署 BPMN 是否实际引用发起人组织上下文变量，按需查询对应数据。
3. 同一流程定义的变量需求只解析一次；新部署版本使用新的流程定义 ID，自然重新解析。
4. 使用启动前已经解析、校验过的明确流程定义 ID 发起实例，避免 Flowable 再按 Key 重复解析最新定义。
5. 可信 Session 的用户 ID 与发起人一致时复用 Session 真实姓名，避免低代码委托发起重复查询用户资料。
6. BPMN 解析失败时保守回退到全部上下文查询，确保旧模型、自定义扩展和异常模型不因优化改变行为。
7. 保留调用方传入的全部流程变量，不改变幂等 `businessKey`、状态机、审批路由及同步待办创建语义。

## 3. 设计

### 3.1 Admin → Flow HTTP 连接复用

- 使用专用 Apache HttpClient 5 连接池和 `HttpComponentsClientHttpRequestFactory` 构造 `flowRestTemplate`。
- 连接池、调度器只服务于 Flow 客户端，不与受 SSRF 防护约束的通用出站客户端混用。
- 新增连接池申请超时、连接池总连接数、单路由连接数、保活时间和空闲校验时间配置；保留现有连接超时和读取超时配置键。
- request factory 作为 Spring Bean 管理，应用关闭时释放调度线程和连接池。
- 连接池申请超时限制高并发排队时间，防止连接耗尽时无限等待。

### 3.2 BPMN 发起人上下文按需加载

- 从已经由 Flowable 加载的 `BpmnModel` 转换出的完整 BPMN XML 中识别变量标识，覆盖节点属性、条件表达式、监听器和扩展字段。
- 识别以下上下文需求：
  - `initiatorLeader`
  - `regionCode` / `startUserRegionCode`
  - `startUserRoleIds`
  - `startUserActiveOrgId`
  - `startUserOrgIds`
- 仅当相应变量在 BPMN 中出现时，执行领导、用户区域、角色或组织查询。
- 调用方已经传入但 BPMN 未静态引用的变量仍原样进入流程变量 Map，不做删除或过滤。
- 变量需求缓存按不可变的 `processDefinitionId` 建键，最多保留 512 个定义；超限按插入顺序淘汰。
- 无法读取或转换 BPMN，或模型包含委托类、脚本任务、调用活动、任务/执行监听器等无法静态确定变量读取范围的执行点时，返回“全部需要”，以正确性优先。

### 3.3 使用已解析的流程定义启动

- 启动前查询得到的最新 `ProcessDefinition` 同时用于 BPMN 读取、业务关联和实例启动。
- 调用 `startProcessInstanceById(processDefinitionId, businessKey, variables)`，不再让 Flowable 按 `modelKey` 重复选择一次最新版本。
- 新部署版本仍会在下一次发起的定义查询中生效；单次请求内始终使用同一个不可变定义。

### 3.4 复用可信发起人姓名

- 当当前 Flow Session 的 `userId` 与流程发起人 ID 一致，且 Session 中 `realName` 非空时，直接使用该真实姓名。
- Session 缺失、用户不一致或真实姓名为空时，保留现有组织服务与用户服务查询兜底。
- 不直接信任普通请求体中的 `userName`，避免用性能优化放宽身份可信边界。

## 4. 非目标与边界

- 不将 `TASK_CREATED` 待办镜像、业务关联写入或流程启动改成异步。
- 不改变 Flowable 最新定义查询、按需部署、幂等锁和事务边界。
- 不缓存具体用户的领导、角色、组织或区域数据，避免组织变更后读到陈旧结果。
- 不调整前端交互和第一阶段已完成的后台运行态校准。
- 不自动启动或重启用户本地 Admin/Flow 服务，不写入真实业务数据。

## 5. 风险与回退

- 风险：BPMN 自定义代码可能在 Java/脚本内部读取变量，变量名不出现在模型里。措施：扫描完整序列化 XML；发现委托类、脚本、调用活动或监听器时全部加载；转换失败时全部加载；测试覆盖属性、条件和调用方变量保留。
- 风险：连接池配置不合理造成排队。措施：提供默认值和配置项，整次调用超时包含排队时间，单主机并发不超过总并发。
- 回退：恢复 `SimpleClientHttpRequestFactory`，并将组织上下文分支恢复为无条件加载；本轮无数据库变更。

## 6. 验收标准

- [x] 默认自动配置创建池化的 Flow HTTP request factory，并正确应用超时和并发参数。
- [x] 无组织上下文变量的 BPMN 不再查询领导、区域、角色和组织。
- [x] 引用某类变量时只加载对应上下文，变量值与优化前一致。
- [x] BPMN 解析失败时回退全部加载，调用方传入变量不丢失。
- [x] 同一流程定义重复发起不重复解析变量需求，缓存上限有效。
- [x] 流程实例按启动前已校验的定义 ID 创建，不再按 Key 重复解析定义。
- [x] 可信委托发起复用 Session 真实姓名，非可信场景保留原查询兜底。
- [x] Flow 客户端及流程插件定向测试、JDK 17 编译和 `git diff --check` 通过，或明确记录环境限制。
