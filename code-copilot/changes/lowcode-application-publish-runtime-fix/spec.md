# 低代码应用发布与子表运行时修复规格

## 背景

应用内表单完成设计并发布后，当前存在三类相互关联的问题：

1. 应用真实运行页仍显示“静态结构预览”，并可能拦截新增提交。
2. 表单设计器中配置的关联子表没有稳定编译进已发布 CRUD 运行配置，导致发布后子表不渲染。
3. 应用发布完成后，纳入发布范围的业务对象必须处于 `PUBLISHED` 状态；不能出现应用版本成功但对象仍为草稿/待发布的半发布状态。

## 目标

- 只有设计画布的静态预览模式显示静态预览提示并阻止提交。
- 已发布应用运行页始终使用已发布 CRUD 接口，正常查询、打开表单和提交。
- 子表组件无论位于单表单根组件，还是多表单 `forms[*].schema.components` 中，都能同步为对象关系并编译为 `masterDetailConfig.children`。
- 应用协调发布结束前校验全部选中对象的发布结果，确保对象状态与发布版本完整落库。
- 保持设计预览的安全边界：未开启真实数据预览时仍不请求或写入真实接口。

## 范围

### 前端

- 修正 `GridBlockRenderer` 的静态 CRUD 预览判定。
- 将判定提取为可测试的共享函数，覆盖设计态、草稿真实预览和正式运行态。
- 保持运行配置中的 `childrenConfig` 原样下发给 `AiCrudPage`。

### 后端

- 完善表单 Schema 子表组件遍历，覆盖根组件、嵌套 children、多表单 schema 组件。
- 发布前从持久化表单 Schema 重新同步子表关系，再生成页面模型引用和运行配置。
- 应用发布前准备全部关联对象的运行草稿，发布对象步骤结束后重新读取对象状态并校验选中对象均已发布且有发布版本。

## 非目标

- 不改变既有主子表保存协议和 merge/replace 语义。
- 不自动发布未纳入当前应用发布选择的外部共享对象。
- 不修改业务数据或历史发布版本。

## 验收标准

1. 已发布应用列表页不再出现“静态结构预览”提示，新增/编辑提交不被静态预览守卫拦截。
2. 设计器未开启真实数据预览时仍显示静态提示并禁止提交。
3. 配置了目标对象与字段的子表在应用发布后出现在新增、编辑和详情表单中。
4. 多表单 Schema 中的子表同样能建立运行关系。
5. 应用发布成功后，所有选中对象的 `design_status` 为 `PUBLISHED`，并存在有效发布版本。
6. 前端定向测试、后端定向测试、Lint/编译和 `git diff --check` 通过。

## 风险与回滚

- 子表关系同步会新增或更新自动管理的 `CHILD_LIST` 关系以及子对象外键字段；逻辑仅作用于表单子表组件声明的目标对象。
- 发布后置校验只阻止错误的“假成功”，不改变发布事务外已有的恢复机制。
- 回滚可恢复本变更代码；已生成的自动关系继续由设计器现有删除/同步逻辑管理。
