# 低代码子表列表字段发布修复 Spec

> 变更名：`lowcode-child-list-columns`
> 状态：`implemented`（草稿表头/取数一致性修复及真实数据库只读回放通过，运行进程需加载新代码）
> 创建日期：2026-09-20

## 1. 问题

1. 列表设计器可以选中子表字段，但子表对象上该字段的 `listVisible=false` 时，发布编译再次按 `listVisible` 过滤，导致正式运行配置没有该列。
2. 子表列标题被发布编译和设计预览自动加上“子表名 ·”前缀，与用户期望的简洁字段标题不一致。
3. 列表画布已保存 `modelCode__field`，但 form-first `viewSchema` 只按主模型字段清洗，导致
   `pageSchema.zones[table]` 被回写成仅主表字段；发布编译又只读 table zone，最终丢失子表列。

## 2. 目标

- 列表 `table.fieldRefs` 显式选中的子表字段必须进入已发布 `columnsSchema`，不受子表对象默认 `listVisible` 影响。
- 未显式选择子表字段时，仍遵循原默认列策略，不自动把全部子表字段加入列表。
- 设计预览和正式运行列标题只展示字段名；子表归属仅在字段选择面板中分组说明。
- 保持“聚合到一行 / 拆成多条”、主表主键操作去重及既有主子表查询语义不变。
- 列表网格显式选列作为发布编译的优先事实来源，并兼容修复历史上 grid 与 table zone 不一致的草稿。

## 3. 验收标准

- [x] 选中 `listVisible=false` 的子表字段后，发布产物包含对应列。
- [x] 子表列的 `key/dataIndex` 保持带模型编码的唯一字段引用，但 `title` 仅显示字段名。
- [x] 设计预览与发布后标题一致。
- [x] 历史草稿即使 table zone 缺失子表字段，只要列表 grid 已保存选列，重新发布后仍生成子表列。
- [x] 定向前后端测试、前端构建和静态检查通过。

## 4. 增量：子表列出现但没有数据

真实接口确认：设计预览 render 已生成 3 个子表列，`page?designPreview=1` 却只返回主表键；同一记录的详情存在子表行。表头会即时编译草稿，数据查询仍使用缓存实体中的旧 `columnsSchema`，导致未进入子表 JOIN 查询。

- 草稿表头与数据查询复用同一个运行配置编译入口，包含搜索、列、表单、选项和翻译/加密配置。
- 编译只修改配置副本，不写数据库、不覆盖缓存、不修改发布快照。
- 保持设计权限校验和已发布版本隔离，不允许普通请求读取未发布草稿。
- 保持聚合/拆行、租户隔离、逻辑删除及主表操作语义；不修改业务数据、审批状态、权限规则或数据库结构。
- [x] 回归覆盖完整的配置解析 → JOIN SQL 投影 → 返回字段别名/值，不能只断言列存在。

验证结果：38 个定向测试通过；真实配置只读回放覆盖 16 条主记录、48 个子表单元格，全部与子表原始值一致；拆行 17 行、17 个唯一行键。未重启用户的 Admin 服务，未进行浏览器端到端验收。
