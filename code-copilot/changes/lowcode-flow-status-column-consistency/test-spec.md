# 低代码业务流程状态字段与列表运行配置一致性测试计划

## P0 后端单元与集成测试

## P0 整列消失定位断言

- 调用正式运行接口（不带设计预览参数）时，断言返回的 `columns` 是否包含 `flowStatus`；该接口缺列时归类为发布快照问题。
- 当正式运行接口返回 `flowStatus` 而页面不显示时，使用旧 `fieldRefs`、缺少 `managedBy` 的字段目录和显式隐藏配置分别验证前端过滤行为。
- 测试必须同时覆盖“后端响应缺列”和“后端响应有列但前端过滤掉”两条路径，避免只验证状态值回写。

1. 一致性服务
   - 空字段时幂等创建 `flowStatus` 和 `flow_status`。
   - 已有标准字段时重复调用不重复创建列、字段或列表引用。
   - 只有 `flowStatus`、只有 `flow_status`、只有 `business_flow_status` 特征且缺少 `managedBy` 时均能识别并补齐托管元数据。
   - 字段编码、列名、类型、长度或字典冲突时返回结构化错误。
   - 明确禁用或隐藏的字段不被强制改为可见。

2. 流程绑定与流程保存
   - 仅保存绑定配置也会确保字段和默认列表引用。
   - 审批节点缺少 `statusField` 时保存后绑定 `flowStatus`。
   - 已绑定字段重复保存保持幂等。
   - 缺少 `ai:lowcode:deploy-ddl` 权限时事务失败，绑定不会留下成功假象。
   - 非 `BUSINESS_OBJECT_FORM` 节点不误触发对象字段创建；稳定应用表单引用仍能正确识别。

3. 发布快照与版本选择
   - 已发布对象草稿新增流程状态字段后，直接发布应用生成新对象/CRUD 版本。
   - 对象状态仍为 `PUBLISHED` 但结构摘要已漂移时不得复用旧版本。
   - 发布快照缺少字段或列时，发布前修复并持久化，或阻断并返回原因。
   - 对象、CRUD、应用版本任一未完成时应用发布不得返回成功。

4. 运行时正式/草稿隔离
   - 正式运行配置读取发布版本，不读取未发布草稿。
   - 发布版本含字段时正式列表包含审批状态列。
   - 历史发布版本缺字段但草稿有字段时，自愈结果可持久化且下一次请求稳定一致。

## P0 前端测试

- 旧页面区块 `fieldRefs` 不含 `flowStatus` 时，运行列补偿加入托管字段。
- `fieldCatalog` 缺少 `managedBy` 但含 `flowStatus/flow_status/business_flow_status` 时，前端仍能识别托管字段。
- `fieldSettings.flowStatus.visible === false` 时不补入可见列。
- 自动补字段接口失败时显示 warning/阻断保存或发布，不再静默成功。
- 自动补齐成功后刷新 fields、页面 Schema、运行配置和页面区块引用。
- 正式门户不带设计预览参数，设计预览仍可读取草稿且不写入正式配置。

## P1 回归与静态检查

- 多审批节点、多次打开节点和重复发布的幂等回归。
- 列表列顺序、操作列、用户自定义隐藏和子表列不受影响。
- 租户隔离、权限校验、事务回滚和逻辑删除查询不回归。
- 检查新增写接口不使用固定字段的 `@RequestBody Map`，状态判断使用枚举或已有常量。
- 执行 Generator/Flow 相关 Maven 定向测试和编译。
- 执行前端 Vitest、ESLint、生产构建及 `git diff --check`。

## 暂不执行

- 不自动启动 Admin、Flow、MySQL、Redis，也不操作真实生产流程实例。
- 不批量修复历史业务数据；历史漂移数据由人工选择对象后执行受控补偿。
- 真实环境需验证：绑定流程后直接发布应用、重启服务、刷新正式列表，审批状态列仍存在且状态值可正常回写。
