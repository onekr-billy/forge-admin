# 低代码业务流程状态字段与列表运行配置一致性修复 Tasks

## T1 复现与基线

- [ ] 使用“已发布业务对象 + 已发布低代码应用 + 审批流程绑定”的最小数据集复现字段消失。
- [ ] 记录对象草稿、`ai_crud_config`、`ai_crud_config_version`、应用页面区块和流程 Schema 中的 `flowStatus/flow_status` 状态。
- [ ] 验证不重新打开审批节点直接发布、重新打开节点后发布两条路径的差异。
- [x] 确认当前工作区已有改动不被覆盖，并记录本变更不修改业务代码的基线。

## T2 抽取一致性能力

- [ ] 新增统一的业务流程运行配置一致性服务，集中字段识别、元数据规范化、列表引用合并和快照漂移检测。
- [x] 为旧字段补齐 `advancedProps.managedBy=BUSINESS_FLOW`、字典、字段状态和列表可见性；冲突字段必须阻断。
- [x] 确保 `flowStatus`、`flow_status`、`business_flow_status` 的识别规则在后端和前端一致。
- [x] 保持租户、权限、事务和逻辑删除约束，禁止在 Service 中重新引入未审计的动态 SQL。

## T3 统一触发入口

- [x] 在流程绑定保存入口调用一致性服务，保证只保存绑定关系不会跳过字段和运行配置准备。
- [x] 在流程 Schema 保存和流程发布入口调用一致性服务，确保审批节点 `statusField` 规范化。
- [x] 在业务对象发布前通过字段确保逻辑标记已发布对象为 `CHANGED`，避免复用明显过期版本。
- [ ] 复用旧对象版本前增加字段/列表/页面 Schema 一致性校验；存在托管字段变更时生成新版本。
- [ ] 发布后校验对象版本、CRUD 版本和应用页面快照均已包含一致的流程状态字段。

## T4 运行时和前端补偿

- [x] 运行时对历史发布快照补齐缺失的模型字段和列表列（正式发布仍通过正常发布流程持久化）。
- [x] 依靠 CRUD 配置缓存失效和对象草稿保存，避免继续复用旧运行配置。
- [ ] 前端自动补字段失败时显示 warning，并在保存/发布检查中阻断半成功提交。（本轮未改动节点 UI，待后续专项处理）
- [x] 自动补齐成功后刷新 fields、page schema、runtime config 和页面区块 `fieldRefs`。
- [x] 保留用户显式隐藏 `flowStatus` 的配置，不因平台补偿强制显示。

## T5 巨型类边界整理

- [ ] 从 `AiCrudConfigService` 移出复杂的托管字段识别/修复细节，保留运行配置装配入口。
