# 低代码应用设计体验与页面形态优化 Spec

## 目标

分阶段修复低代码应用创建和设计体验，并补齐左树右表、树形加载及子表顺序配置能力，确保设计态保存、运行态渲染和流程任务表单使用同一份稳定协议。

## 范围与阶段

### 阶段一：创建页面体验与业务编码唯一性（本轮先落地）

1. 新建页面进入表单/列表设计器期间始终显示设计器专用骨架或加载占位，不出现大面积空白；页面对象、表单资产和草稿加载完成后再切换到设计器。
2. 业务对象编码（`objectCode`）和页面编码（`pageKey`/页面业务编码，若由后端持久化）必须在租户/应用作用域内唯一。前端提供异步校验和明确错误文案，后端保存/创建接口做最终校验并返回可识别的冲突错误。
3. 唯一校验必须排除当前编辑记录，且不能只依赖前端正则或内存中的页面列表。

### 阶段二：左树右表设计器和模板

1. 列表页面设计器提供单表 CRUD、左树右表两种内置模板，模板切换保留可兼容的字段配置并支持撤销前确认。
2. 将旧版树字段迁移为面向业务用户的配置：树数据、树标题、节点标识、父级字段、显示字段、加载方式、节点关联值和右表过滤字段。技术字段只在高级设置展开，并保留旧字段别名读取能力。
3. 保存时统一输出 `treeConfig`，同时生成 `apiConfig.tree`；缺少旧字段时按兼容规则归一化，不丢失树配置。

### 阶段三：树形页面运行时

1. 表单+列表页面支持左树右表布局，树节点点击向右表追加稳定的过滤条件；清空节点恢复无树过滤。
2. 全量加载一次取得树数据并构造层级；懒加载按父节点请求，传递字符串化的父节点值并正确标记叶子节点。
3. 树数据来源、节点取值字段和右表过滤字段职责分离；接口错误、空树和无子节点有明确空态，不影响右表基础查询。

### 阶段四：子表字段与筛选条件排序

1. 子表展示字段和筛选条件在设计器中竖向展示，支持拖拽排序、键盘可访问的上下移动和删除/恢复默认顺序。
2. 顺序保存为 schema 数组顺序，并在设计预览、运行态 CRUD、流程审批任务表单三条渲染链路中严格复用。
3. 旧版只有集合没有顺序时按字段目录稳定顺序迁移；未知字段被过滤但不能导致整个子表配置丢失。

### 阶段五：流程状态专项与巨型类治理（后续）

1. 对审批状态整列消失建立可重复回归场景，覆盖流程绑定、对象草稿、列表选列、发布版本和运行时配置五个快照层。
2. 将流程状态修复从通用流程服务中抽出，保证绑定后不需要重新打开流程节点才能恢复列，同时不覆盖用户显式隐藏。
3. 按 `giant-class-audit.md` 分批拆分低代码/流程巨型类和前端巨型 SFC；每批保持协议兼容并单独验证。

## 非功能与约束

- 后端写接口使用明确 DTO，动态业务记录/流程变量除外；复杂查询写 Mapper XML。
- 低代码设计器跨组件状态使用 Pinia，不继续增加多层 props/emit 透传。
- 页面滚动区域必须有明确高度和 `min-height: 0`，不通过大面积装饰掩盖加载问题。
- 不新增硬编码密钥、租户 `0` 数据或物理删除设计态主数据。
- 雪花 ID 和节点值在前端以字符串处理，避免精度丢失。

## 验收标准

- 新建页面从点击确认到设计器可用期间无白屏空档，失败时可见错误且可重试。
- 相同租户下重复业务编码在前端输入后给出冲突提示，绕过前端直接调用接口仍被后端拒绝；编辑自身编码不误报。
- 左树右表模板可创建、保存、重新打开并运行；全量/懒加载和节点过滤行为可由自动化测试证明。
- 子表展示字段和筛选条件的顺序在保存、预览、运行、审批任务表单中一致。

## 风险与回滚

- 阶段一仅改创建加载态和编码校验，数据库结构不变，可独立回滚。
- 阶段二/三若发现旧版配置无法归一化，应保留原始 `treeConfig` 并降级为普通列表，不阻断页面打开。
- 阶段四只新增顺序字段/数组语义，不删除旧字段；运行时遇到非法顺序回退稳定目录顺序。
