# 开放平台注册与接入体验

## 目标
在独立 worktree `forge-admin-main` 的 `codex/open-platform-experience` 分支开发，H5 工作区不参与。
把能力目录、注册配置、机器客户端整理为业务人员能理解的开放平台。统一能力注册入口，支持流程操作、低代码应用页面/表单、系统 REST 接口；为后续低代码应用内嵌注册保留可复用组件与上下文。

## 用户路径
- 能力目录解释“开放哪些功能”，接入系统解释“谁能调用”，授权与调用记录沿用现有路由。
- 注册先选场景，再选来源和输入字段，最后确认发布；能力编码默认生成，技术设置按需展开。
- 低代码优先选择应用及已发布页面，兼容直接选择业务对象和原有版本升级。
- 客户端创建先说明后台服务/真实用户两种执行方式，创建后进入同一客户端的授权和调用工作台。
- 列表名称与编码合并，保留两项高频操作，其余收进更多；统一明暗主题与窄屏滚动。

## 执行边界
- 复用现有能力不可变版本、客户端授权、可信身份、字段白名单、幂等和审计。
- 流程撤回必须复用平台业务流程服务及发起人校验；不通过直接改状态实现。
- REST 仅开放可受控绑定的系统接口；不能允许 URL 任意转发、伪造身份、绕过租户和原接口权限。接口签名发生变化时拒绝旧版本执行。
- 页面不是可执行动作；表单填报必须绑定发布态表单及后端保存协议，不把 OPEN_PAGE 当成写数据。
- 权限/状态流转属于敏感改动：验收需人工审查对应差异及真实环境的权限交集。未经授权不连接生产库、不执行真实流程、不部署。

## 验收
1. 首次进入能明确分辨能力与接入系统，并找到注册、授权、测试入口。
2. 注册来源加载、不可用原因、版本升级、失败重试有可见反馈，提交防重复。
3. 三类注册契约可用于现有网关调用指南，旧能力仍可使用。
4. 配置组件按职责拆分并使用 Pinia 共享状态，单个 SFC 不超过 800 行。
5. 前端定向测试、ESLint、构建与浏览器检查；后端目标模块测试/编译，记录环境限制。

## 范围外
本轮不将入口嵌入低代码设计器，不变更 H5，不发布远端，不自动启用/授权全部能力。

## 本轮协议与上线审查边界
- REST 使用 `@OpenRestCapability` 显式纳管，支持声明路径/查询参数及明确 JSON DTO 的同步 `RespInfo` 接口；不任意代理 URL。接口代码须使用可信执行上下文，不依赖 Servlet/原始 Sa-Token 会话、MVC 拦截器或响应加密 advice。签名和版本指纹固定；复杂鉴权、异步/流式接口需专用定义。内置纳管一个租户字典选项读取接口作为可用示例。
- 表单通用填报首期面向主库单表表单，模型白名单、模型必填、单据控制字段排除和动态 CRUD 校验共同生效。主子表、结构化字段、外部数据源显示明确不可用原因，继续使用具备完整契约的业务动作；不能把不完整输入静默保存。
- 新增 `ai_capability_form_receipt` 是原子建单幂等运行回执，仅保存摘要和记录 ID，不保存表单/凭据。建单及回执同一事务，失败整体回滚；不提供普通业务删除。上线前审核 V1.0.181 / V1.0.182。回退应用不删除回执；权限资源停用及回执归档需另行审批。
- 新增系统能力调用/字典读取权限资源不自动授予普通角色或客户端。管理员需检查业务权限、客户端授权及用户委托身份交集。
- 菜单仅将内置“机器客户端”改为“接入系统”，保留自定义名称和全部资源 ID、路由、授权。回滚可恢复原内置名称；不删除回执和历史能力版本。
- 当前代码与模拟验证完成；真实环境人工审查、迁移及端到端验收未完成，不将单元测试或预览夹具作为生产验收结论。
