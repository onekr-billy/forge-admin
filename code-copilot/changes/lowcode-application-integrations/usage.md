# 应用集成与开放：使用及上线说明

## 入口

应用中心 → 进入应用设计器 → 设置 → **集成与开放**。

四个页签分别为：企业协同、对外能力、接入授权、调用记录。应用未发布时可以配置连接，但不能注册对外能力；先发布并启用应用。平台管理员仍统一管理连接凭据和接入系统，应用中仅保存引用。

## 企业协同

1. 在平台“企业协同 → 连接管理”维护企业微信连接，按需配置启用的 LOGIN / MESSAGE 应用。免登还需要开启工作台免登、配置可信域名和账号绑定；消息接收人也需要绑定企业身份。
2. 在应用中选择连接并“保存绑定”，绑定引用保存后生效，不需要重新发布应用。页面的“配置齐全”表示凭据和能力配置满足检查，不代表已经完成外部平台连通性验证。未保存的选择会单独提示，不会覆盖已保存连接的实际状态。
3. 复制“企业微信工作台应用主页”到企业微信应用设置。地址沿用当前站点部署前缀和路由模式，不包含 Secret。企业微信客户端内走免登，普通浏览器仍正常登录。
4. 需要通知时，在应用业务流程增加“发送消息”节点，选择已有模板，勾选“通过本应用企业协同通道发送”，发布流程。**本期收件人是流程发起人**，模板参数提供 objectCode、recordId、processCode；不自动插入通知节点。原有触发器/动作的接收人规则不变。
5. 节点完成表示消息进入消息中心发送链路；实际投递结果、失败原因和重试状态到消息中心查看，不在能力调用记录中查找。

取消绑定会停用 `app_<应用ID>_collaboration` 通道，后续节点不降级到默认连接或站内信。不会删除历史消息、平台连接或客户端授权，也不会强制退出已有会话；已分发的链接仍受中央免登开关及应用权限控制，不能把“解绑”当成撤销所有登录资格。

“刷新状态”会保留未保存的连接选择；只有“保存绑定”才写入。如果提示配置已被他人修改，先刷新、核对当前绑定，再决定是否保存。模板在流程发布后被停用或删除，执行时会明确失败；应用专属通道类型被错误修改时也会拒绝发送。

连接配置和接入系统工作台均在当前页展开，可用顶部返回按钮回到原列表；只有应用凭据、能力绑定和授权等单次编辑使用局部弹窗。凭据编辑时 Secret 留空保留原值，保存期间不能重复提交或关闭弹窗。

**本次升级的历史数据注意项：**如果旧版本在连接只有 LOGIN、尚未配置 MESSAGE 时保存过应用绑定，其专属消息通道可能遗留停用状态。升级后在该应用的“企业协同”页点击一次“重新应用配置”同步；无需解绑再绑定。新版本不再把保存时的消息可用状态固化到通道启用标记，实际发送仍逐次检查中央连接、MESSAGE 应用、凭据、模板及接收人身份；不会因重新应用配置而跳过这些校验。

当前不包含企业微信待办同步、钉钉或飞书适配。

## 对外能力与授权

从应用内点击“注册能力”会直接进入当前应用的表单填报配置，不再先选择“低代码应用”或重新选择应用；只有多个已发布页面时才需选择页面。需要流程/系统 REST 时可点“上一步”更换场景，应用关联仍固定。平台全局入口继续允许选择应用。加载来源期间会显示对应场景的 loading，失败可重新加载。

1. “对外能力 → 注册能力”，按引导选择本应用已发布的页面/业务对象与流程操作，或选择显式纳管的系统 REST。应用来源锁定，不展示其他应用对象。REST 不接受任意 URL；接口须已使用平台纳管协议。
2. 核对来源、字段范围和生成的能力编码后发布。已有能力用“发布新版本”升级，应用重新发布不会自动改变对外契约。
3. “接入授权”先选择一项应用能力，再选择平台已有的接入系统。默认固定当前版本，可设失效时间；授权继承已发布字段范围，不绕过真实调用人的业务权限。
4. “调用指南”查看请求契约；“调用记录”只查询当前选择的能力，可按 requestId 筛选。没有选择能力时不查询全平台数据。
5. 撤销授权只影响该系统的该项能力，不删除接入系统或其他能力授权。

外部表单填报支持已发布、可写的单表，包括应用自动创建的运行表。主子表/复杂结构化字段仍不在此入口范围。历史平台能力不自动归入应用，历史客户端授权不自动扩大。

### 自动建表如何开放填报？

在当前应用的“对外能力”选择表单填报，选择已发布页面和允许填写的字段后发布。无需填写新增接口地址、重建表或创建业务动作。开放调用和页面的 `POST /ai/crud/{configKey}` 共用新增业务入口，由原动态 CRUD 处理校验、数据源路由和保存，并保留原创建事件。外部系统仍通过开放网关鉴权调用，不能跳过网关直连内部接口。

本次修复移除了把运行数据源一概拒绝的适配层限制，不向运行库加表、不增加新的数据库迁移。需部署更新后的 Admin 和前端；此前注册被拦截的表单可重新选择并注册。平台已有 `V1.0.182` 回执表仍须按正常版本迁移存在。

调用同一请求应保持 `Idempotency-Key` 不变，成功后重复请求返回原 `recordId`。独立运行库发生超时、进程中断或回执保存异常时，可能已新增但结果未确认：系统返回 `FORM_SUBMISSION_UNCERTAIN` 并保留平台占位，不会自动再次新增。先在应用记录与调用日志中核对，由管理员确认处理；不要自动换键重试、清空回执或把错误响应等同于业务没有保存。普通新增的跨库调用并非分布式原子事务，本次没有承诺自动恢复或消息恰好投递一次。

业务消息中的 `app_<应用ID>_collaboration` 是系统生成的内部路由标识，不是要填写的配置项。它已放入“技术详情（无需手工配置）”，日常只需进入业务流程配置通知节点、模板和发送条件。页面“发送连接已配置”不等于通知规则已启用；沿用现有流程/消息中心链路，不绑定即发信。

### 应用中配置了业务流程，如何开放启动？

在“注册能力 → 流程操作”选择“应用业务流程”，再选择页面及其已发布业务流程。应用内入口自动带入当前应用；页面仅有一个可用流程会自动选中，多个流程必须明确选择。列表只读取该应用发布快照，不要求在旧“对象主流程”再绑定一次审批模型。

调用时传入已经保存的表单记录 `recordId`，系统沿用应用业务流程编排器，执行其中配置的审批、条件、业务动作等节点。需要先建单时使用“表单填报”能力取得记录 ID，再调用启动能力；不把两次调用描述为原子事务。“发起业务流程”不等同于审批任务同意、驳回或撤回。此入口仅支持手动开始的业务流程，事件/定时流程会显示不可用原因。

需更新并重启 Admin，同时更新前端资源，无新增 SQL。若目标流程已在当前应用发布快照中，无需补旧主流程配置或仅为此次修复重新发布应用；若只有流程草稿/新流程版本而应用快照尚未包含，则仍需正常发布应用。应用或流程版本变化后，原能力不会偷偷切换到新流程，需要审核并“发布能力新版本”。既有旧版对象审批能力保持兼容，不自动迁移。

外部调用使用用户委托，保留业务流程启动权限、节点自定义权限和记录数据范围检查，不能传入用户、租户、审批模型或任意流程变量。同一流程版本和记录复用原运行；已有失败运行不会因外部重复调用自动重试，请在原业务流程运行记录中核对后按权限处理。本轮未部署或执行真实审批，以上路径还需测试环境验收。

## 权限和部署

应用内注册若遇到“来源不属于当前应用的已发布版本”，本次修复针对旧应用快照遗漏对象 suiteCode 的误判。升级并重启 Admin 后可直接重试注册，无需补 SQL、修改历史快照或仅为该缺字段问题重新发布应用；新快照会自动保存该字段。来源必须确实存在于已发布快照：后来新增到草稿的对象仍需发布应用，已删除后同编码重建的对象也不能冒用旧对象身份。本项仅后端变更，不要求更新前端资源。

- 查看要求应用查看权限与对应平台查看权限；修改要求应用编辑权限与对应协同修改/能力发布/授权权限。仅有应用编辑权不会获取连接凭据或平台授权能力。
- 开放平台右上角导航使用 `/open-platform/capability-*` 正式路由，同时兼容 `/ai/capability/*` 旧地址。调用记录和能力授权为隐藏工具页，分别要求原有的 `ai:capability:invocation:query`、`ai:capability:grant:query` 权限；别名不会扩大权限，后端接口继续独立鉴权。
- 从 `codex/open-platform-experience` 独立工作树构建 Admin 与 UI。本轮未修改 H5 工作树。
- 人工审查 V1.0.183 后，按项目正常 Flyway 启动迁移；此分支还包含上一期 V1.0.181 / V1.0.182，必须按版本顺序部署。**不要对已有库重跑全量初始化 SQL**。
- V1.0.183 只创建 `ai_application_integration` / `ai_application_capability`，不导入演示、日志、连接密钥或客户端授权。沿用既有迁移历史表检查结果。
- 部署前检查既有消息模板、连接可用性、接收人身份映射；不要把 mock 组件验收结果当成真实企业微信联调通过。

## 必须补做的环境验收

- 两人同时编辑绑定：过期 revision 拒绝，不覆盖新配置；跨租户连接/应用外对象/能力 ID 拒绝。
- 发布能力关联失败时整笔事务回滚；固定版本授权不随新版本自动扩大。
- 企业微信免登后回到原应用页面；关闭免登开关后，新授权及回调均拒绝。
- 审批异步完成后通知发起人；通道停用/解绑/身份未绑定的失败状态可追踪，无默认连接降级。
- 真实表单填报、流程操作和 REST 调用成功且可通过 requestId 关联审计；撤销后拒绝。

回滚代码前先停用新增的应用通知节点/通道，避免旧版本遇到未支持通道类型。新增表和历史消息/调用记录保留；如需撤销授权，请在平台正常撤销，不通过删表处理。
