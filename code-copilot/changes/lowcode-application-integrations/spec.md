# 低代码应用：集成与开放

## 目标与范围
- 在应用设计器的设置中增加“集成与开放”，企业协同、对外能力、接入授权、调用记录四个页签；不修改 H5 工作树。
- 企业协同绑定租户内已有连接，只保存引用，不复制凭据。显示 LOGIN/MESSAGE 配置可用性（不代表外部平台连通性已验收）；生成 PC 门户免登入口和应用专属消息通道。仍须显式配置模板和发送消息步骤，接收人按下述范围处理，不自动添加通知。钉钉、飞书、企业微信 TODO 同步不在本期。
- 能力注册复用现有三步注册器，锁定当前应用；流程/表单/业务动作仅允许已发布应用包含的对象。REST 仍仅允许显式纳管接口。发布与应用关联同事务。
- 新业务流程的 SEND_MESSAGE 节点支持站内信或本应用协同连接，接收人明确为流程发起人，使用运行实例+节点幂等键。存量触发器/业务动作继续保留其接收人规则；不宣称本期已提供新的任意收件人设计器。
- 应用能力目录由服务端按租户/应用关联分页；授权和调用记录按选定的应用能力查询，禁止空选择退化成全局列表。复用现有调用指南与权限、身份、版本、审计链路。
- 应用绑定配置独立于草稿/发布快照，保存立即生效，采用 revision 乐观并发。已发布能力采用独立不可变版本，不因重新发布应用自动更新。

## 安全与人工审查门槛
- 配置写入同时要求应用编辑及协同配置权限；能力发布/授权/日志同时要求应用访问与原开放平台权限。不得因应用编辑权取得全局开放权限。
- 所有查询显式 tenant_id，来源采用正式应用快照校验，应用内发布不能更新其他应用的同名能力。
- 消息连接被停用/跨租户/解绑必须失败关闭，不退回默认连接或站内信；仅发送已配置规则产生的消息。
- URL 仅使用本站门户地址及后端连接编码，无密钥；免登继续服务端 OAuth state/一次性票据，应用可见性不绕过。
- 免登授权与回调同时校验连接启用和工作台免登开关；保存/恢复应用深链不跳转到外站。应用解绑只停用应用消息通道，不撤销平台连接、已有登录会话或已分发链接的中央登录资格。
- 审批异步回调可使用已验证的 TenantContextHolder 租户，无交互会话不伪造用户；缺少租户或处于忽略租户模式时拒绝企业协同消息。
- 涉及授权、外部消息和数据库迁移，部署前由人工审查。此次不运行数据库/真实发信/真实授权，不启动 Admin/Flow。

## 数据及兼容

## 验收
入口可发现、切换应用无旧请求污染、未发布/无权限/空态/错误可解释；小屏及深色可读；取消不写入；保存/发布/授权防双击；跨应用/租户拒绝；消息真实经过 COLLABORATION 链路。

## 本地增量收尾（2026-09-22）
- 配置刷新不得覆盖正在编辑的连接选择；保存开始后，之前的读取响应失效，保存中不再启动同域配置刷新。
- 消息执行前重新确认模板仍启用；发布后模板被停用或删除必须明确失败，不创建空消息。
- 应用专属通道类型漂移、企业协同开关不是布尔值或节点缺失稳定 ID 时拒绝执行，不静默降级为站内信或共享错误幂等键。
- 只做本地代码、定向测试及组件回归；真实环境验收门槛不变。

## 控制台细节与配置闭环（2026-09-22）
- 开放平台补齐菜单路径对应的真实路由，并兼容原文件路由；两种地址共享原菜单授权。调用记录/授权页面此前被隐藏且导航 SQL 不返回，额外按登录用户原平台对应查看权限判定，仅这两个工具页适用，不加入登录白名单、不扩大后端权限。
- 企业协同从叠层弹窗调整为同页连接配置工作区，保留列表状态；应用凭据使用单层局部表单。统一主题、密度、滚动、窄屏及错误状态。
- 应用集成改为紧凑配置分区，明确当前应用、未保存选择、配置条件与执行入口；配置齐全不等于平台连通或消息投递成功。
- 逐项检查连接、平台应用、能力绑定、应用绑定的保存/回显/运行时读取；修复配置漂移和异步回写。应用消息通道的启停表达是否绑定，平台 MESSAGE 是否可执行继续在每次实际发送时校验，不缓存保存时能力快照；解绑仍停用且不降级。
- 不执行真实数据库、发信、审批或部署。安全/状态语义差异保持上线人工审查要求。

## 注册响应与业务可理解性（2026-09-22）
- 选择场景立即进入配置并显示区域 loading；按 serviceCode 查询来源，REST 不扫描表单/流程，隔离迟到请求。
- 应用内注册默认进入当前应用表单填报，自动带入应用名称且不可重选；仍可返回选择流程/REST，发布保持服务端归属校验。
- 自动建表也使用受管运行数据源，现有填报能力仅支持主库单表，不能将有 datasourceId 等同为用户手工外接。明确开放接口限制及原子性风险，修复空编码误判；不直接删除事务保护或迁移现有表。
- 业务消息默认解释通知对象、触发条件和配置操作；通道编码移入折叠技术详情，明确系统生成无需填写。
- 复用已有测试与浏览器夹具；真实数据库、外部投递、部署和推送不在本轮操作范围。

## 自动建表的开放填报（按用户确认路线修订）
- 开放填报复用 POST /ai/crud/{configKey} 的新增业务链路，不通过 HTTP 自调用、不新增另一套建单引擎。页面接口与开放适配层共用新增协调器，统一 DynamicCrudService.insert、数据源路由、字段校验及创建事件。
- 已发布且可写的单表不再因 datasourceId 被拒绝；仍保留发布快照、用户委托、租户、对象权限、字段白名单及主子表/结构化字段限制。
- 撤销未完成的运行库回执初始化及连接池改造；不新增迁移，不向运行库建技术表，不要求重新建业务表或增加业务动作。
- 复用平台已有 ai_capability_form_receipt。主库单表维持建单与回执同事务；独立运行库在调用既有新增逻辑前，先持久化唯一请求占位。成功保存 recordId 后同键返回原记录；同键不同正文/身份/版本拒绝。占位已有但未完成时拒绝再次新增。
- 跨库写入异常、进程退出或回执保存失败时无法断言业务未创建，返回 FORM_SUBMISSION_UNCERTAIN，要求核对应用记录，禁止自动换键重试。此为保守的至多一次执行保护，不宣称跨库原子提交或自动恢复；不删除失败占位，不开发新对账管理平台。
- 公共新增协调器在所属事务提交后发出既有业务创建事件，回滚不派发；异步事件不是持久 Outbox，仍不承诺消息/流程 exactly-once。不自动新增送审逻辑，保留用户配置的既有事件行为。
- 不改变客户端授权、权限资源或业务状态机。真实 MySQL、网关/消息 E2E 由用户执行；本轮仅代码、隔离测试与构建，不部署或操作业务数据库。

## 应用内能力来源误判修复（2026-09-22）
- 根因：应用对象发布快照未写入 suiteCode，requireSource 却强制用该字段匹配；真实运行快照与旧测试手工构造的 VO 不一致。
- 新发布快照保存对象自己的 suiteCode，不以应用套件替代，支持已引用的跨套件对象。
- 来源按可信租户 + suiteCode + objectCode 查询未删除对象，再以不可变 objectId、objectCode 匹配应用已发布快照；快照有 suiteCode 时也必须一致。历史快照缺少 suiteCode 只兼容字段缺失，不放宽对象 ID 归属。
- 不以当前应用草稿对象列表替代发布成员；同编码不同套件、删除后重建的新 ID、未发布新增对象、无租户及缺来源参数均拒绝。
- 不修改存量快照或数据库，不要求仅因该缺字段问题重新发布应用；不扩大授权。回退代码即可撤销修复，已有快照新增字段向后兼容；权限边界保持部署前人工审查。

## 应用业务流程开放（替换旧对象主流程口径）
- 应用页面入口默认注册“应用业务流程”：按应用已发布快照 publishedProcessVersions 和页面对象 ID 选择业务流程，不查询旧 ai_business_binding 主流程。多个流程明确选择，单个自动选中；加载、空态、失败重试与切换隔离遵循 DESIGN。
- 新受控系统能力 lowcode.business-process.start 复用 BusinessProcessOrchestrator；输入为已保存的 recordId，身份来自用户委托，执行整个已发布编排（审批、条件、动作），不抽取审批模型直接启动，不伪装成旧 START/SUBMIT。
- 表单新增仍走已有填报能力；此次不把创建记录和流程启动假装为跨库原子组合，也不把流程启动混同为审批任务同意/驳回/撤回。旧对象审批、独立 BPMN 能力保持兼容，明确标注旧版入口。
- 来源和执行校验可信租户、应用门户可见性、已发布应用/对象/流程身份、手动开始节点、当前启用状态。能力固定 applicationVersion、processVersionId/schemaHash，版本漂移要求审核能力新版本；进入编排器前再次对照固定流程版本，不能执行未经授权的新版本。
- 用户委托须有业务流程启动权限及节点自定义权限；记录通过原动态 CRUD 数据范围读取，无权/不存在拒绝。输入拒绝额外模型/流程/租户/用户/组织/变量，执行沿用编排器的版本+记录幂等；开放入口失败运行不自动重试，交由原有运行记录重试权限处理。
- 应用内发布的 parameters.applicationId 必须等于路由 appId；升级保留原应用/对象/流程，不自动换源。无新数据库迁移，不改旧能力版本或已有配置。涉及状态流转与权限边界，部署前须人工审查；本轮只本地测试/构建/模拟 UI，不操作真实服务、数据库、审批或消息。
