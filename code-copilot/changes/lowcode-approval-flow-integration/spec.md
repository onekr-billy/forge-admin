# 低代码审批流程衔接优化 Spec

> 变更名：`lowcode-approval-flow-integration`
> 状态：`implemented-with-validation-limitations`
> 创建日期：2026-09-18

## 1. 问题与根因

低代码应用的业务流程审批节点点击“新建并设计”后，会同时由节点配置组件和业务流程工作台各自打开一层真实流程设计器。用户关闭上层设计器后，下层设计器仍然存在，表现为灰色遮罩和两层页面嵌套。

新建模型会立即写入审批节点配置，但节点选择器只读取已部署目录；与此同时，业务流程的“可设计模型”目录虽然请求草稿与已发布模型，Flow 服务 `/api/flow/model/list` 却忽略 `status` 并始终只返回已发布模型。结果是新建草稿无法稳定回显，部署后目录刷新与当前选择也可能脱节。

## 2. 目标

1. “新建并设计”和“在本页设计”一次只打开一层流程设计器，由业务流程工作台统一管理弹窗生命周期。
2. 新建模型后立即自动绑定当前审批节点，并以“草稿/待发布”状态稳定回显。
3. 保存流程草稿时保持设计器打开；部署成功后自动刷新目录并把当前模型更新为“已部署”，无需重新选择。
4. 关闭流程设计器后刷新模型目录和预览，当前审批节点仍指向刚创建的模型。
5. 业务流程发布校验仍只接受真实已部署模型，草稿模型不能进入运行态。
6. 前端所有模型 ID 保持字符串，不损失雪花 ID 精度。

## 3. 设计

### 3.1 单一弹窗所有者

- `ActionAndApprovalNodeConfig` 只负责创建/选择模型并发出 `openFlowDesigner` 事件，不再导入、挂载或关闭 `FlowDesignPage`。
- `business-process.[processId].vue` 是内嵌流程设计器的唯一所有者；保存和部署事件只刷新目录，显式关闭才关闭弹窗。
- 工作台保存当前设计会话的模型 ID/Key，使异步目录刷新后仍能定位当前模型。

### 3.2 草稿与已发布目录

- Flow 服务列表接口保留默认“只返回已发布模型”的兼容行为。
- 内部 `FlowClient` 在请求可设计目录时显式传 `includeDraft=true`；服务层/Mapper 按租户、分类和可选状态返回未删除模型。
- 业务流程设计目录返回草稿和已发布模型；发布校验继续用 `status=1` 并再次检查部署标识。

### 3.3 选择与回显

- 审批选择器默认只允许选择已部署模型，避免把任意草稿配置到运行态。
- 当前节点刚创建或已绑定的草稿模型作为一个明确标注“待发布”的当前选项保留，支持继续设计，不因目录刷新消失。
- 新建接口返回后构造乐观目录项，立即写入 `flowModelKey/modelName/modelId`；服务端目录返回后用真实状态替换。
- 预览和“在本页设计”从完整模型目录解析当前模型，不再依赖“已部署模型”过滤结果。

## 4. 非目标

- 不新增第二套审批配置页面，不改变 BPMN 节点审批人、会签、驳回和字段权限的配置位置。
- 不改变业务流程发布时的已部署校验，不允许草稿流程进入运行态。
- 不修改数据库结构或 Flyway 脚本。
- 不在本轮启动真实 Admin/Flow 服务或改动用户数据库。

## 5. 验收标准

- [x] 点击“新建并设计”只出现一个流程设计器，关闭后不再出现第二层。
- [x] 新建模型自动绑定审批节点，选择器显示“待发布”，且“在本页设计”可继续打开同一模型。
- [x] 保存草稿不会关闭设计器；部署后目录自动刷新并显示“已部署”。
- [x] 关闭设计器后审批节点仍选中刚创建的模型，流程图预览可刷新。
- [x] 默认公共流程模型下拉行为不变，仍只返回已发布模型；低代码设计目录能取得草稿。
- [x] 业务流程发布校验继续拒绝未部署模型。
- [ ] 前端定向测试与构建已通过；本机缺少 JDK/Maven，Flow/Generator 后端测试与编译待具备 Java 17 的环境复跑。
